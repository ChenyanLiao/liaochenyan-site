01 / Overview

Keep traceable evidence across a complex preparation workflow.

CHARMM-GUI System Builder organizes input auditing, browser-step capture, long-running job recovery, archive inspection, and GROMACS topology validation into a traceable workflow.

It is not a new molecular-dynamics engine and does not replace CHARMM-GUI. It helps researchers and AI agents record, recover, and verify system preparation more reliably while keeping evidence at each critical boundary.

02 / Why it exists

Failure does not live in one layer.

Dynamic browser forms, asynchronous backend jobs, browser downloads, archive formats, force-field conversion, and scientific approval belong to different failure boundaries. Treating them as one successful task can hide an unsubmitted page, interrupted download, damaged archive, or incomplete topology.

The project records and validates those boundaries separately: browser state is supported by browser evidence, file state by archive and content checks, and scientific readiness by an explicit human approval gate.

03 / Capabilities

From input audit to package validation.

  1. 01

    Audit PDB, SDF, MOL2, and ligand-parameter inputs.

  2. 02

    Capture browser parameters, URLs, screenshots, and job state.

  3. 03

    Check membrane orientation, system dimensions, lipid ratios, and ion settings.

  4. 04

    Distinguish running, stalled, backend complete, and waiting for a human next-step submission.

  5. 05

    Recover interrupted browser downloads while preserving evidence.

  6. 06

    Identify tar, tar.gz, HTML error pages, damaged packages, and incomplete downloads.

  7. 07

    Validate GRO, TOP, ITP, MDP, and system components.

  8. 08

    Check that custom ligand parameters truly enter the final GROMACS topology.

  9. 09

    Prevent a technical file pass from being reported as production-ready.

04 / Cross-agent support

One audit model across multiple agent clients.

The public documentation currently covers the following environments while preserving the same evidence and human-takeover requirements.

  • Codex
  • Claude Code
  • OpenClaw / Javis
  • Hermes Agent
  • Other Agent Skills-compatible clients

Browser assistance depends on whether the runtime provides a browser, computer control, or human takeover. Without those capabilities, the skill does not pretend a browser step was completed.

05 / Scientific boundary

A technical pass is not production approval.

The highest automatic status is Technical_Pass_Not_Production_Approval. File-integrity checks are not expanded into scientific conclusions.

  • It does not issue Production_Approved automatically.
  • It does not run gmx mdrun.
  • It does not use gmx grompp -maxwarn to conceal topology problems.
  • It does not choose membrane composition, protonation, protein segmentation, or ligand parameters for the researcher.
  • It does not describe a prepared structure as binding-site evidence.

Technical_Pass_Not_Production_ApprovalProduction still requires expert review of molecular identity, protonation, parameters, membrane orientation, topology preprocessing, and overall system plausibility.

06 / Origin and acknowledgement

Built from real recovery and validation needs.

The project grew from recurring recovery, archive-identification, and validation needs in real membrane-protein system preparation, then developed through repeated workflow testing into a public skill.

The public page contains no specific unpublished molecule, internal job ID, private structure, personal path, or runtime credential.

Developed with research guidance from Nian Yin and computational workflow support from NianLab.
