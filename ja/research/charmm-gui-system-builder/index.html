CHARMM-GUI System Builder

CHARMM-GUI の入力確認、ブラウザージョブ、ダウンロード復旧、GROMACS ファイル検証を別々の段階として記録する AI エージェント用スキル。

非公式のコミュニティプロジェクトです。CHARMM-GUI、Im Lab、Lehigh University との提携関係はなく、これらの組織から承認を受けたものでもありません。

01 / 概要

ダウンロードの完了だけでは、シミュレーション可能な系とはいえません。

CHARMM-GUI で膜タンパク質系を準備するには、入力構造、ブラウザーフォーム、バックエンドジョブ、ダウンロード、アーカイブ展開、GROMACS トポロジー確認が必要です。ある段階が正常でも、その先の段階まで保証するわけではありません。

このスキルは、送信したパラメータ、ブラウザージョブの停止箇所、取得物がアーカイブか HTML エラーページか、GRO・TOP・ITP・MDP ファイルの整合性を個別に記録します。新しい動力学エンジンではなく、CHARMM-GUI を置き換えるものでもありません。

02 / 開発の背景

ブラウザージョブ、取得したパッケージ、トポロジーでは、失敗する箇所が異なります。

ページが準備済みに見えても送信されていない場合があります。バックエンドが完了してもブラウザーのダウンロードは失敗しえます。.tar.gz という名前のファイルに HTML エラーが入っていることもあります。また、GROMACS ファイルが読めるだけでは、独自のリガンドパラメータが最終トポロジーに反映された証明にはなりません。

このスキルは、これらの違いをひとつのチェックマークでまとめません。ブラウザーの状態は操作記録、ファイルの状態は形式と完全性の確認、トポロジーの状態は構成要素の検査で裏づけます。本番 MD に進めるかどうかは、別途、人が判断します。

03 / 機能

元の構造から GROMACS パッケージまで。

  1. 01

    PDB、SDF、MOL2、リガンドパラメータの入力を点検します。

  2. 02

    ブラウザーのパラメータ、URL、スクリーンショット、ジョブの状態を記録します。

  3. 03

    膜の向き、系の寸法、脂質比、イオン設定を確認します。

  4. 04

    実行中、停滞、バックエンド完了、人による次段階の送信待ちを区別します。

  5. 05

    根拠を残しながら、中断したブラウザーダウンロードを復旧します。

  6. 06

    tar、tar.gz、HTML エラーページ、破損したパッケージ、未完了のダウンロードを識別します。

  7. 07

    GRO、TOP、ITP、MDP と系の構成要素を検証します。

  8. 08

    独自のリガンドパラメータが最終的な GROMACS トポロジーに実際に反映されているか確認します。

  9. 09

    構造環境の台帳を使い、膜のバルク成分と、構造中で同定された脂質、イオン、補因子、ポケット構成要素を区別します。

  10. 10

    構造の整理、配向、組み立て、最終座標変換の各段階で、ポーズが保持されている根拠を記録します。

  11. 11

    拘束ファイル、マクロ、平衡化中の拘束解除スケジュール、想定する本番状態を確認し、未解決の確認事項を次段階へ引き継ぎます。

  12. 12

    個別の読み取り専用監査、明示的なロック、独立した Receipt 2.0 検証を経て Stage 2 を完了します。

  13. 13

    技術的なファイル検査の合格を、本番実行可能と報告することを防ぎます。

04 / 複数エージェントへの対応

異なるエージェントクライアントから、同じ確認を実行できます。

公開版は、確認項目と人への引き継ぎ条件を共通に保ち、以下の環境向けアダプターを提供します。

  • Codex
  • Claude Code
  • OpenClaw / Javis
  • Hermes Agent
  • その他の Agent Skills 対応クライアント

実行環境にブラウザー操作や人への引き継ぎ機能がない場合、スキルはブラウザーの段階で停止します。「実行できない」を「完了」に書き換えません。

05 / 科学的な限界

ファイルが揃っても、本番シミュレーションが許可されるわけではありません。

Stage 2 の確認は、入力、記録、出力ファイルの整合性を確かめるものです。プロトン化状態、膜組成、リガンドパラメータの科学的妥当性を判断するものではなく、トポロジーを前処理できたという理由だけで MD を許可するものでもありません。

  • Production_Approved を自動で発行しません。
  • gmx mdrun は実行しません。
  • gmx grompp -maxwarn でトポロジーの問題を隠しません。
  • 膜組成、プロトン化状態、タンパク質の区分、リガンドパラメータを研究者に代わって選びません。
  • 準備済みの構造を、結合部位の証拠とは表現しません。

production_ready=false · md_execution_allowed=false · no_mdrun=true本番実行の前に、分子の同一性、プロトン化状態、リガンドパラメータ、膜の向き、トポロジー前処理、系全体の妥当性を専門家が引き続き確認します。

06 / 開発の経緯と謝辞

実際に行き詰まった膜系構築から生まれました。

膜系構築で手間がかかるのは、フォームへの一度の入力よりも、長時間ジョブの再開方法、ダウンロード失敗の裏でバックエンド処理が完了しているか、ようやく届いたパッケージが完全かを確かめることです。このプロジェクトは、繰り返し起こる問題を実行可能な確認手順にしています。

公開版には再利用可能な手法のみを含めます。未公表の個別分子、内部ジョブ ID、非公開構造、ローカルパス、実行環境の認証情報は、リポジトリにもこのページにも含めません。

Nian Yin による研究指導と、NianLab による計算ワークフローの支援を受けて開発しました。
