CHARMM-GUI System Builder

01 / 概览

一个“下载完成”，还不是一个能跑的体系。

用 CHARMM-GUI 准备一个跨膜蛋白体系，要经过输入结构、网页表单、后台任务、浏览器下载、压缩包解开和 GROMACS 拓扑检查。任何一步看起来“完成”，都不能替后面的步骤作证。

这个 Skill 把这些环节逐项记下来：提交了什么参数，网页任务停在哪里，下载到的是压缩包还是 HTML 错误页，最终的 GRO、TOP、ITP 和 MDP 是否彼此对应。它不发明新的模拟引擎，也不替代 CHARMM-GUI。

02 / 为什么做它

网页、下载包和拓扑，会在不同地方出错。

网页可能只是把按钮点亮，还没有真正提交；后台可能已经算完，浏览器下载却中断；扩展名写着 `.tar.gz`，文件内容也可能是一张报错页面；GROMACS 文件能够被读取，也不等于配体参数真的进入了最终拓扑。

Skill 不用一个笼统的绿色勾号盖住这些差别。网页状态看网页记录，下载状态检查文件类型和完整性，拓扑状态核对组件；至于体系是否适合进入 production MD，仍然留给研究者单独批准。

03 / 能力

从原始结构，一直检查到 GROMACS 包。

  1. 01

    审计 PDB、SDF、MOL2 与配体参数输入。

  2. 02

    记录网页参数、URL、截图与任务状态。

  3. 03

    检查膜取向、体系尺寸、脂质比例与离子设置。

  4. 04

    区分 running、stalled、backend complete 与需要人工提交下一步。

  5. 05

    恢复浏览器下载中断，并保留恢复证据。

  6. 06

    识别 tar、tar.gz、HTML 错误页、损坏包与未完成下载。

  7. 07

    验证 GRO、TOP、ITP、MDP 与体系组件。

  8. 08

    检查自定义配体参数是否真正进入最终 GROMACS 拓扑。

  9. 09

    用结构环境台账区分普通膜组分与结构解析的脂质、离子、辅因子和口袋组分。

  10. 10

    记录从输入清理、取向、组装到最终坐标的 Pose 保真证据。

  11. 11

    核对约束文件、宏、平衡释放计划与预期生产态，并把未完成义务交接到后续阶段。

  12. 12

    以只读审计、显式锁定和独立验证完成不可变的 Stage 2 Receipt 2.0 收口。

  13. 13

    阻止把技术文件通过误写成 production-ready。

04 / 跨 Agent 支持

同一套检查，可以交给不同 Agent 执行。

公开版本为以下运行环境提供适配，但检查项目和人工接管条件保持一致。

  • Codex
  • Claude Code
  • OpenClaw / Javis
  • Hermes Agent
  • 其他兼容 Agent Skills 的客户端

运行环境没有浏览器控制或人工接管能力时，Skill 会停在需要网页操作的地方，不把“无法执行”写成“已经完成”。

05 / 科学边界

文件齐全，不等于可以直接开始生产模拟。

Stage 2 的检查只能说明输入、记录和输出包彼此对得上。它不会替研究者判断质子化是否合理、膜组成是否合适，也不会因为拓扑能够预处理就自动授权 MD。

  • 不自动给出 Production_Approved。
  • 不运行 gmx mdrun。
  • 不使用 gmx grompp -maxwarn 掩盖拓扑问题。
  • 不替研究者决定膜组成、质子化、蛋白 segmentation 或配体参数。
  • 不把准备好的结构描述成结合位点证据。

production_ready=false · md_execution_allowed=false · no_mdrun=true进入 production 之前，仍需专家检查分子身份、质子化、配体参数、膜方向、拓扑预处理和整个体系是否合理。

06 / 来源与致谢

它从几次真正卡住的体系构建里长出来。

跨膜蛋白体系构建最费时间的地方，常常不是填写一次表单，而是任务跑了很久以后怎样接着做、下载失败后怎样确认后端是否已经完成、拿到文件后怎样知道它不是损坏包。这个项目把这些反复出现的问题整理成了可执行检查。

公开版本只保留可以复用的方法。具体小分子、内部 Job ID、未公开结构、私人路径和运行凭据都不进入仓库或这个页面。

Developed with research guidance from Nian Yin and computational workflow support from NianLab.
