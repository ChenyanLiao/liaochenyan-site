01 / Overview

让复杂准备过程留下可追踪证据。

CHARMM-GUI System Builder 将跨膜蛋白体系准备中的输入审计、网页步骤记录、慢任务恢复、下载包鉴别和 GROMACS 拓扑验证组织成一套可追踪的工作流。

它不是新的分子动力学引擎，也不替代 CHARMM-GUI。它帮助研究者与 AI Agent 更可靠地记录、恢复和验证体系构建过程，并在每个关键边界保留证据。

02 / Why it exists

失败不会只发生在一个地方。

动态网页表单、异步后端任务、浏览器下载、归档格式、力场转换和科学审批属于不同的失败边界。把它们混为一个“任务成功”，很容易掩盖尚未提交、下载中断、归档损坏或拓扑不完整。

项目的目标是把这些边界分开记录和验证：网页状态由网页证据说明，文件状态由归档与内容检查说明，科学就绪程度则由明确的人工审批门槛说明。

03 / Capabilities

从输入审计到结果包验证。

  1. 01

    审计 PDB、SDF、MOL2 与配体参数输入。

  2. 02

    记录网页参数、URL、截图与任务状态。

  3. 03

    检查膜取向、体系尺寸、脂质比例与离子设置。

  4. 04

    区分 running、stalled、backend complete 与需要人工提交下一步。

  5. 05

    恢复浏览器下载中断，并保留恢复证据。

  6. 06

    识别 tar、tar.gz、HTML 错误页、损坏包与未完成下载。

  7. 07

    验证 GRO、TOP、ITP、MDP 与体系组件。

  8. 08

    检查自定义配体参数是否真正进入最终 GROMACS 拓扑。

  9. 09

    用结构环境台账区分普通膜组分与结构解析的脂质、离子、辅因子和口袋组分。

  10. 10

    记录从输入清理、取向、组装到最终坐标的 Pose 保真证据。

  11. 11

    核对约束文件、宏、平衡释放计划与预期生产态，并把未完成义务交接到后续阶段。

  12. 12

    以只读审计、显式锁定和独立验证完成不可变的 Stage 2 Receipt 2.0 收口。

  13. 13

    阻止把技术文件通过误写成 production-ready。

04 / Cross-agent support

同一套审计原则，可由不同 Agent 客户端执行。

当前公开文档覆盖以下 Agent 环境，并保留相同的人工接管与证据要求。

  • Codex
  • Claude Code
  • OpenClaw / Javis
  • Hermes Agent
  • 其他兼容 Agent Skills 的客户端

网页辅助能力取决于运行环境是否具有浏览器、电脑控制或人工接管能力；缺少这些能力时，Skill 不会假装已经完成网页步骤。

05 / Scientific boundary

技术通过，不等于生产级批准。

该 Skill 的技术收口只证明合同、证据与输出包在 Stage 2 的一致性；即使环境一致性通过，也不会把文件检查扩张成科学结论或 MD 授权。

  • 不自动给出 Production_Approved。
  • 不运行 gmx mdrun。
  • 不使用 gmx grompp -maxwarn 掩盖拓扑问题。
  • 不替研究者决定膜组成、质子化、蛋白 segmentation 或配体参数。
  • 不把准备好的结构描述成结合位点证据。

production_ready=false · md_execution_allowed=false · no_mdrun=trueProduction 仍需专家审核分子身份、质子化、参数、膜方向、拓扑预处理与体系合理性。

06 / Origin and acknowledgement

来自真实工作流中的恢复与验证需求。

项目来自跨膜蛋白体系构建中反复出现的真实恢复、归档鉴别和验证需求，并通过多轮工作流测试逐步整理为公开 Skill。
