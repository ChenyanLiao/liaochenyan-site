MolloM · 开发版手册 · 2026.10.24

MolloM 完整使用手册

从电脑上的第一项计算，到手机里的进度与结果。

这份手册从第一项对接任务讲起，继续介绍结果筛选、分子动力学、波函数分析，以及如何在手机上查看进展、整理记录和提交计划。可以按顺序阅读，也可以从目录直接进入正在使用的功能。

本文对应 2026 年 10 月 24 日核对的开发界面，供已获得开发版本的使用者查阅。正式安装包开放后，下载入口会更新在 MolloM 页面。配图使用隔离的演示数据；按钮名称以简体中文界面为准。

1. 从哪里开始

1.1 先选一条要完成的路线

第一次使用，建议先完成一个规模很小、自己熟悉的任务。准备一个受体和少量配体，走通导入、准备、设置搜索盒、试跑和查看结果，再扩大到整批分子。

已有 GROMACS 体系的读者可以直接从第 10 章开始；已有波函数文件，可以读第 12 章。手机的连接、查看和计划操作从第 13 章开始。对接与 MD 都有各自的入口，无需为了使用其中一项先完成另一项。

1.2 分清操作位置和计算位置

桌面端用于准备结构、配置程序、安排计算和检查结果。执行位置可以是当前电脑，也可以是通过 SSH 连接的服务器。程序、输入路径和计算资源都要按所选机器填写：服务器上的路径由服务器读取，本机路径由本机读取。

手机连接监控服务后，可以查看所绑定设备提供的运行、结果和日志，也可以在授权有效期内编辑待提交计划。离开电脑前，应确认计算机器不会休眠，监控服务能够继续运行。

1.3 找到项目与设置

打开“项目与模板”，可以“新建项目”“打开项目 JSON”，也可以“载入公开示例”熟悉界面。在“设置”选择界面语言；手册中的中文名称对应简体中文界面。

初次试用公开示例时，先检查示例文件、计算环境和搜索范围，再启动小规模试跑。模板中的数值是起点，需要根据自己的结构和研究目的调整。

2. 连接计算环境并准备软件

2.1 在本机运行

  1. 打开“计算环境与软件中心”，执行位置选择“本机运行”。
  2. 点击“重新探测”，查看程序和环境的探测结果。
  3. 已有对接程序时，用“指定 Vina 可执行文件”或相应引擎的程序选择入口指定实际文件。
  4. 检查工作目录是否可写、磁盘空间是否足够。

路径检查完成后，再做一次小规模真实试跑。启动程序时缺少动态库、模型文件或设备驱动的问题，通常会在这一步暴露出来。

2.2 连接 SSH 服务器

  1. 添加服务器，填写“主机 / SSH Config 别名”。已有系统 SSH 配置时可以使用别名。
  2. 根据配置填写用户名、端口，选择系统认证或密钥文件。不要把私钥正文粘进普通输入框。
  3. 填写服务器工作目录、远端程序路径；需要指定 Python 时，填写服务器上的 Python 路径。
  4. “保存服务器”后，点击“测试连接并探测环境”。

首次连接需要核对服务器主机指纹。遇到未知主机或认证失败，应先完成系统 SSH 认证，再回到 MolloM 测试。路径存在但程序无法启动时，查看探测信息，检查权限、依赖和运行环境。

使用集群时选择相应调度方式，再填写分区或队列、账户及资源。对接支持直接运行、Slurm 和 PBS；MD 流程目前提供直接运行与 Slurm。资源填写应符合所在集群的规定。

2.3 用软件中心安装或接入已有程序

进入“软件中心”，先选择本机或目标服务器，点击“刷新”查看该环境的软件记录。需要安装时选择版本，点击“安装”，阅读“安装与验证方案”，确认安装位置、许可和依赖后再“开始执行”。

已有安装可以“重新验证”，通过后选择“使用此版本”。部分软件提供的是官方安装说明或已有程序接入入口，应按对应页面完成准备。遇到验证失败，先阅读该条记录的输出；不要仅因目录已经生成就开始整批任务。

3. 新建项目与导入结构

3.1 建立一个便于回看的项目

在“项目与模板”点击“新建项目”，填写能辨认研究对象与用途的项目名称，再“进入项目”。一个项目中可以保留多次任务和筛选轮次，没必要为每次小调整都复制整套文件。

修改重要配置后点击“保存项目”。“导出 JSON”适合保存项目设置；需要把输入与结果一起搬到另一台电脑，使用第 9 章的项目包。

3.2 添加受体与配体

  1. 进入“受体与配体”，点击“添加受体”，选择 PDB 或 PDBQT 文件。
  2. 配体可以“选择文件”“选择文件夹”，也可以从服务器浏览文件。
  3. 当前输入入口支持 PDBQT、SDF/SD、MOL2、MOL 和 SMILES；按来源选择正确格式。
  4. 点击“重新检查输入”，核对识别记录数、引擎格式输入和解析问题。

一个 SDF 文件可能包含多条记录，因此文件数与分子记录数可能不同。先查看有问题的记录，再决定修正、排除或重新准备。不要在未弄清缺失记录的情况下直接扩大计算。

3.3 保存清楚的来源

保留原始文件及可追溯的分子标识。后续准备可能产生不同工作态，筛选时要能找回它们共同的母体。给受体起易辨认的名称，尤其是在同一项目里比较多个结构或构象时。

原始输入不需要手工改成程序输出格式后再覆盖。结构准备会输出工作副本，下一章介绍如何核对这些变化。

4. 准备受体与配体

4.1 确认受体中保留什么

在“结构准备”填写需要的链；留空时保留全部。根据体系决定是否移除普通水分子，以及是否保留 HETATM 辅因子或金属。结合口袋中有功能水、金属或辅因子时，先依据结构和文献判断其作用。

检查缺失残基、非标准残基和质子化状态。当前准备流程遇到不支持的结构会报告问题，缺失环和目标 pH 下的质子化需要另行处理。

4.2 处理配体工作态

根据输入选择是否取最大母体、是否枚举互变异构工作态，以及每条来源记录允许的工作态数量。未定义手性默认会被隔离；只有明确知道如何处理该批输入时，才使用允许未定义手性的选项。

没有三维坐标的输入需要生成三维结构。无论输入来自数据库还是自己绘制，都应检查电荷、手性和成键关系，再用于后续对接。

4.3 检查准备前后的变化

点击“准备输入并检查”，结束后查看成功和问题记录，使用“打开准备目录”查看产物。在“结构准备前后对比”选择结构，点击“查看变化”，核对重原子、形式电荷、片段和坐标。

对准备失败的记录按具体原因修正。重试时保留原文件，重新生成工作副本，避免覆盖后无法判断变化来自哪里。

5. 在三维视图中设置搜索范围

5.1 找到目标口袋

进入“三维口袋”，选择“对应受体”。用蛋白、配体和表面显示开关查看局部环境，拖动旋转、滚轮缩放，必要时“重置视角”。

有参考配体时，可以使用“选择参考配体定位”帮助确定位置。参考配体必须与当前受体处在同一坐标系；来自另一个结构的坐标，需要先完成合适的结构对齐。

5.2 核对搜索盒

在“搜索盒设置”填写中心 XYZ 和边长 XYZ，单位为 Å。逐个检查盒子是否覆盖希望搜索的区域、是否容纳配体，以及是否大到把大量无关空间也包括进去。

多个受体需要分别核对搜索盒。不要只复制同一组数字就开始批量运行。设置完成后保存项目，并在试跑结果中确认输出姿态位于预期区域。

6. 配置对接引擎与资源

6.1 选择并检查引擎

在“对接引擎库”按名称或类别找到程序，查看“官方资料”，点击“用于本轮”。在“任务方案”指定目标机器上的可执行程序，并“检查程序路径”。

优先使用已配置的内置接入。自定义原生协议适合熟悉目标程序命令和输出格式的使用者，应先用小任务检查输入、命令与结果解析，再扩大规模。

6.2 设置 Vina 参数与独立 seed

选择 Vina 后，填写搜索强度、输出 pose 上限、能量窗口和评分函数。增加搜索强度会增加计算开销，应结合试跑判断，而不是一开始就把所有数值调到最高。

填写独立 seed 列表，每个 seed 对应一次独立搜索。输入数量、启用的受体数量和 seed 数量共同决定任务规模。提交前再次核对本轮名称和任务总数，避免多选受体或重复 seed 带来额外计算。

6.3 使用 GNINA

选择 GNINA 后，按任务目的设置 CNN 使用方式，例如重评分或参与精修，再选择模型；留空时使用引擎默认模型。需要纯 CPU 运行时使用“仅使用 CPU（禁用 GPU）”。

GPU 路径需要同时核对软件、驱动和资源分配，试跑后查看日志中的实际执行情况。结果中的能量、CNNscore 和 CNNaffinity 各有含义与排序方向，筛选时分别设置条件。

6.4 分配并发与 CPU、GPU

“每任务 CPU 配额”控制单项任务使用的 CPU，“并发任务数”控制同时运行的任务数量。两者相乘应与分配到的 CPU 资源相协调，还要为系统和数据读写留出空间。

集群任务还需核对队列、时间、内存和 GPU 申请。填写后先试跑，观察运行速度和内存占用，再决定整批资源。多开并发不一定更快，磁盘、显存或 CPU 争用都可能拖慢整批任务。

7. 小样本试跑与批量任务

7.1 先确认能正确完成一小批

进入“试跑与估时”，设置抽样配体数，点击“开始真实试跑”，再“查看试跑任务”。这一步会实际运行程序并使用所选机器的资源。

试跑完成后检查输出姿态、结果解析和日志。估时根据当前样本与配置计算，不包含排队、准备、传输及导出时间。换引擎、模型、搜索强度或机器后，应重新试跑。

7.2 提交整批计算

进入“任务与进度”，核对准备输入、受体、seed 和资源配置，点击“提交新对接任务”。用“查看参数”确认这次运行实际保存的配置。

观察完成、失败和待处理数量。需要定位异常时打开“运行事件与原始日志”或“打开运行目录”。修改项目中的下一轮参数后，应新建运行，以免混淆不同条件下得到的结果。

7.3 暂停、取消和恢复

“暂停领取”会停止领取新任务，已经开始的任务继续执行；准备好后点击“继续”。“取消剩余任务”用于停止剩余工作，已生成的结果仍保留。

失败后使用“选择失败项重试”，只处理需要重试的项，并保留成功结果和尝试记录。网络中断或状态未知时，先恢复连接并刷新原任务，不要立即重复提交。关闭桌面窗口后，独立执行器可以继续工作；计算机器休眠、关机或任务被调度器终止，则需要另外处理。

8. 筛选结果并建立下一轮

8.1 找到值得继续看的记录

在“结果与筛选”选择运行，通过名称搜索、主阈值或高级多指标条件筛选，然后“应用筛选”。查看每条记录的姿态、来源和指标，而不只盯着第一列分数。

同一条 pose 需要满足所设置的条件。来自不同评分方法的数值应按各自含义解释，不要直接平均。对接结果用于挑选下一步要检查的结构和候选，活性及结合方式仍要结合独立证据判断。

8.2 控制重复并保留多样性

需要压缩候选数量时，可按母体保留一个代表，或按 RDKit 骨架限制代表数。先确认这是否符合研究目的：如果正在比较工作态，过早合并可能丢掉想观察的差异。

检查筛选后数量，再逐项勾选希望继续处理的记录。对异常高分、明显碰撞或不合理构象，先查输入与准备过程。

8.3 创建下一轮

打开“筛选轮次”，选择已结束的运行，设置条件后点击“统计候选数”。填写下一轮名称和引擎，选择复制原始准备输入，或使用本轮评分最优的达标 pose。

点击“选择目录·创建下一轮”，检查生成的输入和配置，再进入任务页面试跑或提交。创建轮次后可以继续修改方案，不会立刻开始计算。

9. 导出结果与搬迁项目

9.1 导出要交给合作者的内容

进入“结构与结果导出”，选择当前筛选结果，或勾选“仅导出勾选记录”。按需要导出 CSV、结构、受体、配置和报告；需要多个姿态时选择所有达标 pose。

检查导出报告中的成功与失败记录。缺少可靠原子映射时，SDF 转换可能失败，保留的 PDBQT 与报告可用于继续排查。不要把缺失的结构文件当作已成功交付。较大的导出任务可暂停，并从检查点恢复。

9.2 建立可携带项目包

在“可携带项目包”预览要带走的内容。需要服务器上的输入时，选择包含远端输入；需要结果时，选择已结束任务的结果，再“选择目录并导出”。

在另一台电脑点击“导入项目包”，选择包中的 Project.htvs.json，检查预览后“确认导入为独立项目”。随后重新配置目标机器的软件、认证和路径。历史结果供查看与比较，新计算应从导入后的项目重新建立任务。

9.3 管理磁盘空间

在“项目与空间”使用“扫描空间与引用”，先看清文件用途和引用关系，再处理缓存。“清理预览中的安全缓存”只应用于预览列出的可清理项。

对原始输入、正式结果和准备过程记录，应按照自己的备份计划保留。移动项目时优先使用项目包，避免只搬了配置文件却遗漏实际输入。

10. 准备分子动力学体系

10.1 选择合适的入口

打开“分子动力学 · GROMACS”。标准蛋白 PDB 可以从“体系构建”开始；已有坐标、拓扑或 TPR，可以通过“导入或连接体系”检查并接入。

从对接结果继续研究时，使用“对接→MD 交接”中的“生成交接 SDF”，检查原子身份和坐标，再进入配体参数化。先明确力场、质子化、配体电荷和体系组成，再开始构建。

10.2 准备配体与复合物

在“配体参数”选择已配置的 ACPYPE / AmberTools、GAFF 或 GAFF2，填写整数净电荷和电荷方法。依次“检查输入与环境”“准备隔离任务”，确认后“提交计算”，完成后“查看拓扑交接”。

“复合物组装”当前面向 AMBER 干蛋白与 GAFF/GAFF2 单配体。选择蛋白 GRO/TOP、配体 ITP 和结合 pose GRO，核对坐标系、原子顺序及力场兼容性，然后“检查原子对应与输入”。通过后创建隔离复合物，交给体系构建处理溶剂、离子与验证。

10.3 构建溶剂与离子环境

  1. 在“体系构建”选择起点：标准蛋白 PDB、保留拓扑的干体系，或已有完整体系。
  2. 填写计算位置、体系目录和输入文件，点击“检查结构与安装的力场”。
  3. 选择实际可用的力场及匹配水模型，设置盒形、溶质到边界的距离、盐浓度、离子和电中和。
  4. 检查末端及质子化处理，点击“保存构建方案并预览命令”。
  5. 确认后“提交构建”，检查输出，再交给多阶段模拟或 MD 导入。

这里的盒子距离使用 nm，与对接搜索盒的 Å 不同。膜蛋白、特殊残基和复杂辅因子应使用合适的专门准备流程，再导入已准备的体系。构建完成后仍要进行能量最小化与平衡。

10.4 接入已有体系

在“导入或连接体系”选择已有 TPR，或坐标、拓扑与 MDP 的组合。填写目标机器上的体系目录和目录内相对路径，根据需要加入索引、位置限制参考坐标和检查点。

依次“检查 GROMACS 环境”“检查体系”“导入为可提交任务”。检查输入与预处理输出后，再“提交任务”。只需要观察已有计算时选择“仅监控已有目录”。

11. 配置和运行多阶段模拟

11.1 建立流程与独立重复

进入“模拟流程”，选择“创建流程与独立重复”，填写体系与资源，按需要设置独立重复数和起始随机 seed。逐阶段检查 EM、NVT、NPT 和 Production 的输入、MDP 和资源。

内置短流程用于走通工程流程，不能直接当作自己体系的平衡与生产方案。特别检查时间长度、温压耦合、位置限制和约束。确认后“保存流程；不提交计算”。

11.2 编辑 MDP 并核对预处理

点击“浏览 GROMACS 参数”或参数工作台，按原生参数名搜索，查看说明并编辑。核对 integrator、dt、nsteps、输出频率、耦合与约束；模拟总时间由步长和步数共同决定。

导入 MDP 时检查重复键和保留的注释。预处理报错或警告时阅读原文，回到输入和参数修正原因，不靠提高 maxwarn 跳过未弄清的问题。

11.3 启动阶段与分配运行资源

选择“启动当前／下一阶段”，核对运行位置、调度资源和 mdrun 参数。线程、PME、GPU 与队列申请需要相互匹配；先查看短运行的实际日志，再决定长任务资源。

上一阶段结束后检查输出和体系状态，再启动下一阶段。失败或主动停止的阶段先恢复处理，避免跳过必要步骤。

11.4 停止、续跑与检查日志

需要有序停止时点击“保存检查点并停止”。恢复时使用“从检查点续跑”，核对原任务及检查点，再查看日志中的续跑位置。总步数终点表示最终要达到的步数，填写时不要误当作额外追加步数。

用“读取日志”“刷新”查看进展。发现约束错误、能量异常或结构不合理时，先检查体系与参数，必要时回到准备或平衡阶段。跨阶段传递状态与同一阶段断点续跑，应按各自入口处理。

12. 检查轨迹与波函数分析

12.1 添加轨迹并确定分析方法

轨迹停止写入后，在“任务与分析”添加只读分析源，选择 TPR 与 XTC/TRR，按需要加入 EDR 和日志。点击“检查轨迹、原子组与能量项”。

选择时间窗口、抽帧间隔、PBC 处理、参考结构、拟合组与测量组，再选择指标。可以从 RMSD、RMSF、回转半径、SASA、氢键、距离接触与能量开始；PCA、聚类、密度等分析按研究问题和环境中可用工具选择。

自定义原子选择应先“检查实际选择并预览”。例如在蛋白拟合后测量配体 RMSD，与配体自身拟合后的 RMSD 回答的是不同问题，应在分析记录中写清。

12.2 查看、比较和导出分析

分析完成后打开“分析方法与来源”，核对时间段、选择与参数，再查看曲线或“加载轨迹预览”。曲线中的异常点可以回到对应实际帧检查，避免仅凭平滑或波动幅度判断体系。

需要比较时，在比较区“加载 MD 任务”“加载此任务的分析”“加入比较”，可比较 2–8 条记录。先核对时间窗口、拟合与选择是否一致，再“比较曲线与方法”，按需“导出比较 JSON”。独立重复之间的差异也应保留。

12.3 检查 Multiwfn 输入

打开“Multiwfn · 输入检查”，选择本机或 SSH 环境中的波函数文件，点击“检查输入”。当前入口可检查 FCH/FCHK、单帧 MWFN，以及受支持的非磁性 GTO WFN/WFX。

查看原子、电子、基组、轨道和密度等输入信息，先解决缺失或不匹配项。需要准备程序时进入“管理 Multiwfn 安装”，安装或验证目标环境中的程序。对接 pose 或 MD 帧可以保存为后续量化计算的几何来源；波函数文件需由相应量化计算生成，再导回检查。

12.4 建立分析任务与查看三维密度

在“波函数分析”填写 Multiwfn 程序路径、方法、CPU 线程和超时，点击“预览任务”。确认输入电子态、方法和许可后“保存任务（不计算）”，再单独“提交计算”。

密度任务需填写网格起点、间距和点数，长度单位为 Bohr。检查网格是否覆盖目标区域及总点数是否合理。完成后“加载三维密度”，设置等值面阈值并“更新等值面”。

WFN/WFX 入口当前用于电子密度；其他方法应以输入检查结果和当前可选任务为准。电子态信息缺失时先补齐来源，不根据文件扩展名猜测。

12.5 导出与保留分析档案

通过“导出文件”保存 cube、日志、方法结果及任务设置。需要搬迁时进入“任务档案”，预览后“选择目录并建立档案”；大批复制可暂停与继续。

“导入任务档案”用于离线查阅已有结果。列表可以设置别名、隐藏或移除记录；误移除时在“已移除记录”中“还原记录”。记录管理与原始计算数据分开处理，清理磁盘前仍应核对文件用途。

13. 连接自己的电脑或服务器

离开电脑以后，可以从手机查看计算进展、记录想法，并继续处理待提交计划。先完成服务连接与设备配对，再进入后面的操作。

13.1 连接服务并登录

先在电脑端准备好监控服务，并确认手机可以访问该服务。服务地址由自己的部署或管理者提供；不要把服务器的 SSH 地址填进账号服务地址栏。

  1. 点击底部“我的”，进入“账号与设备”。也可以从“设置”进入“账号、设备与通知”。
  2. 在“服务地址”中填写已配置的地址，点击“连接服务”。
  3. 填写“邮箱”和“密码”，点击“登录”。
  4. 如使用的服务已开放注册，点击“创建新账号”，填写“显示名称”、邮箱和密码后点击“注册”。若页面要求验证邮箱，完成邮件验证后点击“返回登录”，再登录。

检查结果： 登录表单收起，页面显示当前账号和“我的监控设备”。没有已绑定设备时，继续完成配对。

常见失败与恢复： 连接失败时先核对服务地址和电脑端服务是否运行。登录失效时重新登录；提示需要验证邮箱时，可点击“重新发送验证邮件”，再检查收件箱和垃圾邮件。服务尚未配置邮件时，应先由管理者完成配置，反复点击不会解决问题。“本机只读连接”用于当前设备上的本地服务，不是连接另一台电脑的快捷方式。

13.2 用一次性配对码绑定设备

  1. 在电脑端监控 Agent 生成新的配对码，确认电脑与手机使用同一个服务地址。
  2. 回到手机“账号与设备”，在“一次性配对码”中输入该码，点击“绑定设备”。
  3. 手机提示等待电脑确认后，回到电脑端核对并确认申请绑定的账号。
  4. 在手机点击“刷新设备”。

检查结果： 电脑出现在“我的监控设备”中。手机确认只是配对的第一步，电脑端确认完成后才能正常选择设备。

常见失败与恢复： 配对码无效、已使用或已过期时，在电脑端重新生成，不要继续重复使用旧码。一直停在等待确认时，核对电脑端是否已确认正确账号，以及两端服务地址是否相同。

13.3 选择要查看的设备

  1. 在“我的监控设备”找到目标电脑，检查设备名称、最近联系时间和状态报告时间。
  2. 点击“查看此设备”，返回“进展”。
  3. 如需切换电脑，重新打开“我的”，在另一台电脑的卡片上点击“查看此设备”。

检查结果： 已选设备有选中标记；首页按当前连接显示运行。计算可能在所选电脑本机，也可能由它连接的服务器执行，查看运行时还要核对“本机计算”或“远程计算”。

常见失败与恢复： 设备列表尚未确认时先点“刷新设备”。设备断连时检查电脑是否休眠、监控 Agent 是否运行以及网络是否可用；断连本身不表示计算已经失败。不要把一条运行的连接异常当成全部设备都已离线。

13.4 查看访问权限与解除绑定

  1. 打开“我的”，点击“刷新设备”，查看设备卡片上的权限说明和授权有效期。
  2. 只查看运行时，使用当前查看权限即可。需要修改计划或提交计算时，在电脑端为该设备开启相应限时授权，再回手机刷新。计划操作见第 18 章。
  3. 不再使用某台设备时，先导出需要保留的研究记录，再点击该设备的“解除绑定”，阅读提示后确认。

检查结果： 刷新后权限说明与电脑端授权相符。解绑后，该设备不再向此账号继续提供监控内容；已有计算仍在原电脑或服务器上运行。

常见失败与恢复： 权限未确认或已到期时，回电脑端检查授权，再点“刷新设备”，不要反复尝试不可用的编辑按钮。解绑、退出账号或切换连接前，应先处理需要保留的本机记录；相关本机副本会按页面提示清理。

14. 找到运行并读懂进展

14.1 从进展首页找到需要处理的运行

  1. 点击底部“进展”。
  2. 查看“任务概览”中的“全部运行”“进行中”和“需关注”；点击相应统计进入对应运行列表。
  3. 在“最近运行”中找到目标，点击“查看详情”。需要更多记录时，点击“查看全部运行与项目”。
  4. 在详情中同时查看“计算端更新”和“成功读取”时间：前者表示计算端数据的更新时间，后者表示手机成功取得数据的时间。

检查结果： 运行名称、项目、计算类型和计算位置符合要查看的对象。看到“上次进度”或“状态未知”时，按最后一次读取的信息理解，不当作实时进度。

常见失败与恢复： 首页没有预期运行时，先核对所选设备，再进入“研究”搜索。读取尚未完成或连接中断时，检查连接后点击刷新图标“刷新任务”，不需要重新提交计算。

14.2 按项目、类型和状态查找运行

  1. 点击底部“研究”，在“搜索名称、项目或编号”中输入要找的名称或关键词。
  2. 用“全部项目”和“全部计算类型”选择项目及 Docking、MD 等类型。
  3. 根据需要选择“全部”“进行中”“需关注”或“已完成”。展开“引擎与计算位置”，继续按引擎、本机或远程计算筛选。
  4. 用“上一页”“下一页”浏览结果；重新开始查找时，点击“清空筛选”。

检查结果： 列表上方显示搜索范围。当前目录搜索覆盖全部分页；账号连接搜索覆盖当前设备已同步的记录，而不是仅搜索屏幕上这一页。

常见失败与恢复： 找不到记录时，先清空筛选再搜索，并确认项目和类型没有选错。如果页面提示只同步了部分记录，范围之外的历史应回电脑端查找。离线时搜索仅覆盖本机保存的副本。

14.3 设置刷新频率与恢复读取

  1. 打开“设置”，在“语言”选择“简体中文”，便于对照本手册。
  2. 在“刷新频率”选择需要的读取间隔，或选择“手动刷新”。当前提供 5 秒、10 秒、15 秒、30 秒、1 分钟、2 分钟和 5 分钟，以及手动刷新。
  3. 回到首页，点击刷新图标“刷新任务”立即读取。结果或日志读取失败时，在详情页点击“重新读取”。

检查结果： 最近成功读取时间更新；选择手动刷新后，不再按固定间隔主动读取。更改刷新频率、关闭页面或锁屏不会暂停计算端的任务。

常见失败与恢复： 时间没有更新时，先查看连接提示。恢复网络后仍无法读取，回“我的”刷新并确认设备，再重新读取；保留下来的旧页面只供参考。

14.4 在消息中心筛选通知并打开对应运行

  1. 登录并配对电脑后，点击底部“消息”，打开“消息中心”；点击“刷新消息”读取最新列表。
  2. 在“阅读状态”选择“全部”“未读”或“已读”；在“事件类型”选择“全部事件”“失败”“完成”或“连接变化”。用“上一页”“下一页”查看较早消息。
  3. 点击消息上的“标为已读”或“标为未读”整理阅读状态。需要处理消息时，点击“查看异常日志”“查看运行”或“查看设备”：App 会切换到通知对应的设备，打开异常日志、运行结果或设备进展首页。成功打开目标后，该消息自动标为已读。
  4. 从失败通知进入任务日志时，核对通知时间和尝试次数。如果页面提示通知对应的尝试与当前尝试不同，下方展示的是当前尝试的日志；旧尝试请回电脑端查看。

检查结果： 消息卡片显示“未读”或“已读”，顶部显示未读数量，筛选后列表随之变化。“已读”只表示消息的阅读状态，不表示故障已经解决。通知描述历史事件，判断当前运行状态仍需查看打开后的进展和读取时间。

常见失败与恢复： 出现登录提示时点击“前往登录”；消息更新失败时检查连接后点“刷新消息”，已加载内容仍保留。没有符合筛选的消息时，先将两个筛选恢复为“全部”和“全部事件”。设备已撤销绑定的通知只保留为历史记录，不能继续跳转；通知或运行不可访问时，核对账号及绑定设备，并回电脑端查找原记录。看到旧尝试提示时，不要用当前日志解释旧通知中的失败。

15. 查看结果与排查日志

15.1 查看 Docking 结果

  1. 在“研究”选择 Docking 运行，点击“查看详情”，打开“结果摘要”。
  2. 对照每项结果的配体、受体、随机种子和尝试次数，确认正在查看哪一次计算。
  3. 查看构象的评分名称、评分数值、“越高越优”或“越低越优”提示，以及已有 QC 记录。
  4. 用“上一页”“下一页”浏览更多结果。想留待比较的构象，可点击“候选记录”，按第 16 章保存。

检查结果： 结果有读取时间，并按任务分页；每项最多展示五个构象。缺失评分或 QC 时按页面的缺失提示处理，不补成零分或“通过”。

常见失败与恢复： 显示“尚无任务结果”时，先检查运行是否仍在排队或计算，再查看日志。读取失败可“重新读取”。不同引擎的分数保留各自含义，不跨引擎平均，也不把分数直接当成结合或活性的实验结论。

15.2 查看 MD 进度、检查点和已有分析

  1. 在“研究”的“全部计算类型”中选择 MD，再打开目标运行的“查看详情”。
  2. 在“结果摘要”查看模拟时间与目标时间、运行速度、步数和检查点情况。
  3. 核对是否从检查点续跑，以及当前显示的尝试和来源尝试。
  4. 如果运行已有分析结果或独立分析记录，查看页面展示的分析摘要；需要继续配置或运行分析时，回到电脑端处理。

检查结果： 页面展示已读取的模拟进度和检查点信息；没有提供的数据保持缺失。检查点“有”表示发现了检查点，不表示手机已经执行续跑。

常见失败与恢复： 没有分析区时，先在电脑端确认是否已生成可读取的分析结果。页面显示可续跑提示时，在电脑端核对并继续；不要把时间达到目标或程序结束写成轨迹已收敛、机制已确认。

15.3 选择正确的日志

  1. 从运行详情切换到“错误与日志”，或点击运行卡片上的同名入口。
  2. 选择“Worker”查看执行端输出，选择“调度器”查看调度相关输出。
  3. 要追查某条 Docking 结果，在该结果下面点击“查看任务日志”。打开后，任务日志标签对应这条结果。
  4. 点击“更早日志”向前查看，点击“最新日志”回到最新可读取内容。

检查结果： 日志区标明读取时间、当前字节范围和总大小。先确认日志类型及尝试次数，再解释具体报错。

常见失败与恢复： “日志尚未生成”不等于日志被清空，可稍后点“最新日志”。从历史消息进入日志时，如页面提示尝试次数不一致，应回对应运行核对，不能把当前日志直接当作那次历史失败的输出。

15.4 搜索、跟随和复制日志

  1. 在“搜索当前日志页”输入关键词，用箭头按钮“上一个匹配”“下一个匹配”定位。
  2. 点击“只看错误关键词”筛选包含相关关键词的行；需要完整上下文时再次点击关闭筛选。
  3. 在连接可用且设置了自动刷新间隔时，点击“跟随最新”。搜索、向上阅读或打开旧日志页会暂停跟随；读完后再次点击“跟随最新”恢复。
  4. 需要复制当前页时，点击“复制本页”。

检查结果： 页面显示匹配数量，跟随开启时按钮显示“正在跟随”。搜索和错误筛选只覆盖当前页，每页最多 16 KiB；行号也是本页行号。“复制本页”复制当前页，不是下载完整日志。

常见失败与恢复： 搜索无匹配时可以翻到更早日志继续找。跟随按钮不可用时，检查是否处于离线副本或“手动刷新”；手动模式可直接点“最新日志”。复制失败时长按选择日志文字。错误关键词只是阅读辅助，还需要结合退出码和前后文判断原因。

16. 写笔记、收藏与对照候选

16.1 为一次运行保存笔记和收藏

  1. 打开运行“查看详情”，点击“运行笔记”。
  2. 需要经常回看的运行，勾选“收藏运行”。
  3. 在“研究处理状态”选择“待查看”“已查看”或“待讨论”，在“备注”写下判断、问题或下一步安排。
  4. 点击“保存记录”。以后从“研究”打开“研究记录”，在“运行笔记”中找到它；点击“编辑记录”可继续修改。

检查结果： 列表显示收藏标记、处理状态、备注和记录更新时间。这里的“已查看”只是研究笔记状态，不会把计算运行改为“已完成”。记录先保存在本机。

常见失败与恢复： 保存失败时保持编辑页，检查本机存储后重试。看不到以前的记录时，先确认当前账号和所选设备。关闭未保存的编辑时会询问是否放弃修改；想保留内容应返回并点“保存记录”。

16.2 将构象加入候选清单

  1. 在 Docking“结果摘要”中找到要记录的构象，点击其“候选记录”。
  2. 核对记录中的来源和评分，再选择“研究处理状态”、填写“备注”。
  3. 点击“保存记录”，从“研究记录”切换到“候选清单”查看。
  4. 点击“查看来源运行”返回原运行；需要更多来源字段时，在记录中展开“查看完整来源”。

检查结果： 候选清单保留所选构象的来源、评分及读取时间，不只是复制一个分数。对同一候选继续使用“编辑记录”，可以更新笔记。

常见失败与恢复： 没有稳定构象标识时，“候选记录”按钮不可用，应先在电脑端核对结果。来源暂时无法打开时，已保存的来源信息仍可查看；恢复对应连接后再点“查看来源运行”。“删除记录”删除的是研究记录，原始计算结果不受影响；如记录已关联同步，应先阅读实际确认提示。

16.3 对照两到四条记录

  1. 打开“研究记录”，选择“运行笔记”或“候选清单”。
  2. 勾选要比较的记录上的“选择用于对照/导出”，选择两到四条。
  3. 点击“对照已选”，进入“结果对照”。
  4. 横向滑动查看不同记录，核对来源、引擎、评分名称、已有参数、读取时间和备注；浅色区域标出不同值。

检查结果： 对照页并列展示已保存信息，缺失项显示为“—”。页面会提示记录上下文是否相同；即便相同，也需要核对具体科学条件。

常见失败与恢复： 少于两条或多于四条时，“对照已选”不可用，调整勾选数量即可。来自不同受体、运行或评分上下文的记录可以并列查看，但不能据此混排或合并评分。若记录过旧，先回来源运行读取并更新需要保存的内容。

16.4 导出摘要并确认保存

  1. 在“研究记录”勾选条目后点击“导出已选”；需要当前类别全部记录时点击“导出此列表”。对照页也可以展开“导出摘要”。
  2. 在“文件格式”选择“Markdown (.md)”或“JSON (.json)”，检查“导出预览”。
  3. Android 界面提供“保存文件”和“分享文件”；iOS 提供“保存或分享文件”；浏览器界面提供“下载文件”。按当前平台显示的按钮继续，并在系统界面选择目的位置或接收应用。
  4. 不需要文件时，也可以点“复制文本”。分享前先检查备注和来源信息，移除不准备对外发送的内容。

检查结果： 在所选保存位置打开文件，或到接收应用确认内容。导出包含已保存记录、备注和来源摘要，不是完整分子库、轨迹或全部计算文件。

常见失败与恢复： 取消系统保存或分享不会删除原记录。导出未完成时可返回重新操作，或用“复制文本”。“已打开系统分享界面”仅表示界面已打开，不能代替目标应用已收到的确认。

17. 保留页面并离线查看

17.1 保存运行摘要和需要的页面

  1. 在连接可用时打开目标运行的“查看详情”，等待读取完成。
  2. 点击“保存运行摘要”。需要结果或日志时，先打开对应页，再点击“保留当前已读取页”。
  3. 翻到其他需要的结果或日志页，逐页读取并保留。
  4. 展开“已保存的结果与日志页”，检查哪些内容标为“已主动保留”，并核对页范围、读取时间和保存时间。

检查结果： 操作成功后显示已保留提示。摘要和每个选定页面分开保存；保存摘要不会自动下载整次运行。后续在线读取会更新对应副本，因此它保存的是最近读过的内容，不是冻结不变的备份。

常见失败与恢复： “保留当前已读取页”不可用时，先等待当前页成功读取。容量已满时，按 17.3 取消不需要的保留后重试；提示本次未保存时，不要把屏幕上的内容当作已经可靠保存。

17.2 离线重开与检查缺页

  1. 保持原账号和原连接，重新打开 App。查看页面上的“离线副本”和原读取时间。
  2. 进入“设置”里的“离线记录”，展开“主动保留的运行”，点击目标运行的“打开已保留资料”。
  3. 在运行详情展开“已保存的结果与日志页”，点击需要的页。
  4. 连接恢复后，回首页点击“刷新任务”；需要更新某页时再重新读取该页。

检查结果： 离线时展示已读副本，保留原始读取时间，不显示为新的实时进展。普通读取也会自动缓存最近内容，主动保留则用于留下明确选择的摘要和页面。

常见失败与恢复： “此页尚未保存”时，从已保存页面列表选择已有页；要取得缺页，需恢复连接后读取。离线列表没有运行时，检查是否切换了账号或设备。退出账号或解除绑定会清理相应本机记录，不能用重新登录保证恢复未导出的内容。

17.3 管理容量和取消保留

  1. 打开“设置 → 离线记录”，查看当前连接、全 App 和主动保留内容的用量。
  2. 在“主动保留的运行”点击“取消保留”，可取消整次运行的主动保留；在运行详情的已保存页面列表中，也可以对单页点击“取消保留”。
  3. 如需取消该运行全部保留，可在详情点击“取消此运行全部保留”，确认后再查看用量。
  4. 只有确定不再需要当前连接的本机副本时，才点击“清除当前连接的离线记录”，阅读确认提示后继续。

检查结果： 当前全 App 上限为 40 个运行、每运行 12 页结果或日志、总计 20 MiB。主动保留占用同一额度，但不会被自动淘汰；取消保留后内容回到可淘汰的自动缓存。清理本机副本不删除服务器上的原始结果。

常见失败与恢复： 取消保留不一定立即让用量变为零，因为自动缓存可能仍在。无法保存或清理时先检查本机存储，保留仍可读取的内容，不用退出账号来代替正常的容量管理。

18. 编辑待提交计划并确认计算

18.1 打开桌面项目或已有计划

  1. 在桌面端保存准备好的项目；手机读取的是已保存内容，不包含桌面尚未保存的修改。
  2. 在桌面端打开“设置 → 手机项目与任务授权”，选择已绑定监控 Agent 的 Device.json，设置授权时长。默认仅允许编辑计划；需要从手机提交计算时，在同一授权页另外勾选“允许手机确认后提交真实计算任务”。勾选授权本身不会启动计算，仍需完成 18.4 的手机确认。
  3. 回手机“我的”，确认已选择正确设备并刷新权限。从“研究”里的“项目与计算计划”点击“打开计划”；也可从登录后的账号页点击“项目与计划”。
  4. 点击“桌面项目”，在目标项目上选择“配置新计划”；或者点击“已保存计划”，对已有计划选择“查看计划”。
  5. 核对项目名称、计算主机、引擎和任务数量，再进入参数设置。

检查结果： 从桌面项目创建的是独立待提交计划，原项目保持不变。已有计划只有处于待提交且尚未开始执行时，才可进入支持的编辑操作。

常见失败与恢复： 没有项目或计划时，先在电脑端确认已保存，再点“刷新计划”。权限失效或与预期不符时，回桌面“设置 → 手机项目与任务授权”核对所选 Device.json 是否属于已绑定的 Agent、授权时长及提交勾选状态，重新授权后回手机刷新。项目提示不能创建移动计划时，回电脑端检查；不要把运行中的任务当成可编辑计划。

18.2 修改参数并恢复本机草稿

Docking 与 MD 在手机上的参数表不同，按当前计划实际显示的字段操作。

  1. Docking 计划可调整“每个配体 CPU 线程”“并行配体数”“搜索强度”“最大 pose 数”“评分函数”和“随机种子”；显示“能量范围（kcal/mol）”时再按需要调整。单个 Box 的表单提供“Box 中心（Å）”“Box 尺寸（Å）”及 X、Y、Z 输入。
  2. GNINA 计划显示“执行模式”，可在“仅 CPU（禁用 GPU）”与“允许使用 GPU（取决于主机）”之间选择；“CNN 评分模式”是当前配置说明，不是此页的编辑控件。项目有多个受体各自的 Box 时，在电脑端修改 Box。
  3. MD 计划可调整“每个 rank 的线程”“MPI rank 数”“GPU 数”“内存（GiB）”“队列时限”“分区”“计算账号”“QoS”“最长运行时间（小时）”和“计算模式”。这里调整执行资源，不修改已有 TPR 中的科学设置。
  4. 编辑后检查“修改已保存在本机，尚未发送到桌面”的提示。重开后可从“本机未保存修改”选择“恢复本机草稿”，用“查看草稿输入”核对原值；联网刷新来源后再继续预览。

检查结果： 输入符合字段标出的单位和范围。本机草稿只是手机保存的输入，尚未保存成电脑端计划，更没有开始计算。随机种子按表单说明用逗号分隔；队列时限按输入框显示的时间格式填写。

常见失败与恢复： 字段标红时修改对应值。桌面来源已改变时，先用“查看草稿输入”保留核对依据，再“删除本机草稿”，按最新来源重新编辑。不要用旧草稿覆盖已变化的项目。出现本机保存失败提示时保持当前页，检查存储后再继续。

18.3 预览差异并保存待提交计划

  1. 在参数表中完成修改后，点击“预览修改”。
  2. 在“确认修改差异”逐项核对“修改前”和“修改后”。从桌面项目创建新计划时，还要核对展示的资源摘要。
  3. 确认修改正确后，点击“确认 · 保存为待提交计划”。
  4. 查看保存提示；有操作回执时，展开“桌面回执已核实”检查此次操作，再回“已保存计划”核对。

检查结果： 页面明确提示“已保存为待提交计划，未提交任何计算”，或提示已保存独立计划、原项目不变。完成这一步只是保存，计算尚未启动。

常见失败与恢复： 修改已有计划时，没有参数变化会提示先修改再预览；从桌面项目配置新计划则可以沿用原参数。预览过期、计划或输入已改变时，返回列表“刷新计划”，重新核对并预览。若显示保存结果未知，保留原操作，使用“查询 / 重试同一次保存”恢复结果，不另建替代计划。

18.4 核对资源、提交并恢复未知结果

  1. 在电脑端为当前设备开启限时“允许提交”，回手机刷新计划。先将本机修改保存到桌面，或明确删除不再需要的本机草稿。
  2. 打开已保存的待提交计划，点击“核对计算提交”。
  3. 在“计算提交确认”检查主机、引擎、任务数量、CPU 与并行数，或 MD 的线程、rank、GPU、内存和队列时限。确认这些资源与自己的使用安排相符。
  4. 勾选“已核对主机、引擎、任务数量及资源，确认启动此次计算。”，再点击“开始计算”。这一步会向计算端提交真实计算，应只对准备执行的计划操作。
  5. 点击“刷新计划状态”。出现关联运行后，用“进度与结果”“报错与 Worker 日志”或“调度器日志”继续查看。

检查结果： 页面先记录提交，再显示计划的当前状态。已提交或排队中不等于计算完成；以刷新后的状态和关联运行信息为准。

常见失败与恢复： “开始计算”不可用时，检查是否已勾选确认、提交授权是否有效，以及是否还有未处理的本机修改。连接中断后出现提交结果未知，使用“恢复同一次提交”或“刷新计划状态”，不要另建计划重复提交。重开 App 后也应回到原账号、原服务和原电脑处理保留的回执。若提示回执存储异常，先恢复本机存储并保留原操作，不通过清空数据绕过它。
