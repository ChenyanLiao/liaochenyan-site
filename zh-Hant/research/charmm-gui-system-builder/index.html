CHARMM-GUI System Builder

把 CHARMM-GUI 構建中的輸入檢查、網頁任務、下載恢復和 GROMACS 檔案核驗分開記錄的 AI Agent Skill。

01 / 概覽

一個“下載完成”，還不是一個能跑的體系。

用 CHARMM-GUI 準備一個跨膜蛋白體系，要經過輸入結構、網頁表單、後台任務、瀏覽器下載、壓縮包解開和 GROMACS 拓撲檢查。任何一步看起來“完成”，都不能替後面的步驟作證。

這個 Skill 把這些環節逐項記下來：提交了甚麼參數，網頁任務停在哪裡，下載到的是壓縮包還是 HTML 錯誤頁，最終的 GRO、TOP、ITP 和 MDP 是否彼此對應。它不發明新的模擬引擎，也不替代 CHARMM-GUI。

02 / 為甚麼做

網頁、下載包和拓撲，會在不同地方出錯。

網頁可能只是把按鈕點亮，還沒有真正提交；後台可能已經算完，瀏覽器下載卻中斷；擴展名寫著 `.tar.gz`，檔案內容也可能是一張報錯頁面；GROMACS 檔案能夠被讀取，也不等於配體參數真的進入了最終拓撲。

Skill 不用一個籠統的綠色勾號蓋住這些差別。網頁狀態看網頁記錄，下載狀態檢查檔案類型和完整性，拓撲狀態核對組件；至於體系是否適合進入 production MD，仍然留給研究者單獨批准。

03 / 能力

從原始結構，一直檢查到 GROMACS 包。

  1. 01

    審計 PDB、SDF、MOL2 與配體參數輸入。

  2. 02

    記錄網頁參數、URL、截圖與任務狀態。

  3. 03

    檢查膜取向、體系尺寸、脂質比例與離子設置。

  4. 04

    區分 running、stalled、backend complete 與需要人工提交下一步。

  5. 05

    恢復瀏覽器下載中斷，並保留恢復證據。

  6. 06

    識別 tar、tar.gz、HTML 錯誤頁、損壞包與未完成下載。

  7. 07

    驗證 GRO、TOP、ITP、MDP 與體系組件。

  8. 08

    檢查自定義配體參數是否真正進入最終 GROMACS 拓撲。

  9. 09

    用結構環境台賬區分普通膜組分與結構解析的脂質、離子、輔因子和口袋組分。

  10. 10

    記錄從輸入清理、取向、組裝到最終坐標的 Pose 保真證據。

  11. 11

    核對約束檔案、宏、平衡釋放計劃與預期生產態，並把未完成義務交接到後續階段。

  12. 12

    以只讀審計、顯式鎖定和獨立驗證完成不可變的 Stage 2 Receipt 2.0 收口。

  13. 13

    阻止把技術檔案通過誤寫成 production-ready。

04 / 跨 Agent 支持

同一套檢查，可以交給不同 Agent 執行。

公開版本為以下運行環境提供適配，但檢查項目和人工接管條件保持一致。

  • Codex
  • Claude Code
  • OpenClaw / Javis
  • Hermes Agent
  • 其他兼容 Agent Skills 的客戶端

運行環境沒有瀏覽器控制或人工接管能力時，Skill 會停在需要網頁操作的地方，不把“無法執行”寫成“已經完成”。

05 / 科學邊界

檔案齊全，不等於可以直接開始生產模擬。

Stage 2 的檢查只能說明輸入、記錄和輸出包彼此對得上。它不會替研究者判斷質子化是否合理、膜組成是否合適，也不會因為拓撲能夠預處理就自動授權 MD。

  • 不自動給出 Production_Approved。
  • 不運行 gmx mdrun。
  • 不使用 gmx grompp -maxwarn 掩蓋拓撲問題。
  • 不替研究者決定膜組成、質子化、蛋白 segmentation 或配體參數。
  • 不把準備好的結構描述成結合位點證據。

production_ready=false · md_execution_allowed=false · no_mdrun=true進入 production 之前，仍需專家檢查分子身份、質子化、配體參數、膜方向、拓撲預處理和整個體系是否合理。

06 / 來源與致謝

它從幾次真正卡住的體系構建里長出來。

跨膜蛋白體系構建最費時間的地方，常常不是填寫一次表單，而是任務跑了很久以後怎樣接著做、下載失敗後怎樣確認後端是否已經完成、拿到檔案後怎樣知道它不是損壞包。這個項目把這些反復出現的問題整理成了可執行檢查。

公開版本只保留可以復用的方法。具體小分子、內部 Job ID、未公開結構、私人路徑和運行憑據都不進入倉庫或這個頁面。

開發過程得到 Nian Yin 的研究指導，以及 NianLab 的計算工作流程支援。
